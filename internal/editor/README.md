# 工程核心与源转写

手动编辑、Agent 与工作流共用 `Engine.Apply(EditRequest)`；一次命令批次是一次修订及一个撤销单位，失败不保留部分变更。`BaseRevision` 防止过期写入，`IdempotencyKey` 只接受相同原请求的重试。工程使用整数帧及有理数帧率，素材入点为微秒。

## 源转写模型

- `Project.Transcripts,omitempty` 保存源转写；旧 schema=1 工程无需这些字段。
- `SourceWord{ID,StartUs,EndUs,Text,SpeakerID?}` 使用源素材左闭右开区间。`SpeakerID` 仅保留调用方提供的信息，本包没有识别说话人。
- `Transcript{ID,AssetID,SourceFingerprint,SourceDurationUs,Language?,Origin?,TimingSource?,RawWords,AcceptedWords,Revision,CaptionTrackID?,CaptionLayout?,Stale?,CaptionExclusions?}`。Origin可为空（旧工程）、asr或tts；tts必须明确original/normalized的真实时间来源，ASR和旧未知来源不能附带TTS时间来源。
- `RawWords` 是接纳时的原始识别证据，纠错只更新 `AcceptedWords` 及其 `Revision`；`SourceDurationUs` 保留取得原始证据时的源边界。原始识别、接受词修订与字幕人工覆盖是三份不同的数据。
- `Clip.CaptionSource,omitempty` 仅属于绑定字幕，包含 `TranscriptID/SourceClipID/WordIDs/TextOverride?/StyleOverride?/Partial?/Stale?`。默认仍逐词，阅读模式可以绑定真实有序多词；原始词可以是字、词或短句。

`Snapshot/CloneProject/Undo/Redo` 深拷贝词数组、排除记录与绑定中的词 ID；会话媒体 URL 仍由工程保存层移除。工程与命令可直接 JSON 编码，不包含 ASR 服务凭据或识别调用。

## 命令契约

| Type | 主要参数 | 行为 |
| --- | --- | --- |
| `accept_transcript` | `Transcript` | 需要新 ID、有效音视频素材和相同的非空源指纹；只读取输入的原始词，将接受词初始化为原始词副本，修订设为 1，不覆盖已有原始识别 |
| `correct_transcript` | `TranscriptID, TranscriptRevision, Words` | 修订必须等于当前接受版本；整份替换接受词，可增删词和修改时间，原始词不变；空词列表表示接受版本没有字幕词 |
| `generate_bound_captions` | `TranscriptID, TrackID?, CaptionLayout?` | 启用该源素材持续派生；可显式设置逐词/阅读布局，未提供时保持当前设置。空轨道选择未锁定字幕轨或创建轨道；同素材旧规则停止，原始词保留 |
| `detach_caption` | `ClipID` | 将该字幕变为静态字幕，保存源/词排除记录以免后续源编辑又生成它 |
| `duplicate_clip` | `ClipID, Clip, IncludeLinked?` | 新片段必须有新 ID 并保留素材归属；默认复制 linked 组并创建新链接组；源复制派生的字幕继承原字幕人工覆盖 |

原有 `update_clip/split_clip/delete_clip` 自动触发派生。普通 `add_clip` 使用启用规则的源也会生成字幕；需要明确继承哪次复用的人工覆盖时使用 `duplicate_clip`。同素材、相同源区间的普通添加会尽可能沿用已有覆盖，但存在多个不同覆盖版本时不承诺推断用户意图。

直接更新绑定字幕可以修改文本、样式和展示轨道，文本/样式变化会记录覆盖标志；时间与速度由源片段决定，手动调整前应解除绑定。直接删除绑定字幕会记录排除，静态 SRT 和普通标题不会成为转写。源分割时跨切口词两侧均保留、标记 Partial；人工文本和样式覆盖随各自源段继承。删除源只移除它的绑定字幕，已解除绑定的静态字幕保留。

## 派生、锁定和源变化

源词先与源片段的精确有理数窗口求交，再按速度映射到工程帧：起点向下、终点向上取整，并限制在源片段帧范围内。可见的极短词仍占至少一帧；共享的非整帧边界可能造成字幕重叠，由独立字幕轨保留词条，不丢词。`MapWordToClip` 与 `ValidateSourceWords` 是纯辅助接口。

同一素材的独立复用分别产生字幕。显式 linked 的音视频在语言、开始帧、长度、源入点与速度相同时选择一个拥有者，视频优先；提取后的音频文件可以具有不同指纹。不同语言或不同映射不合并。重叠词、并行源和静态字幕占用会增加字幕轨；本轮只提供基础层叠偏移，大量同时字幕的最终布局仍需后续阅读体验设计。

任何隐式字幕增删、移动、文本/样式或陈旧标记更新都检查受影响字幕轨的锁定，失败会回滚整批命令。锁定源轨仍遵循原有剪辑规则。同指纹、只修复文件路径的重定位不会改变词时间，允许修复锁轨素材。

源指纹变化会标记 `Transcript.Stale` 和现有绑定的 `Stale`；旧词时间仍作为可追溯证据保存，不静默套用到新内容。陈旧转写不能纠错、重新生成或映射新的源编辑，删除源仍可删除其绑定字幕。需要取得新源的原始转写，再接纳新 ID、显式启用新规则；本包没有调用或伪造 ASR 接口。

## 可持续绑定的阅读分句

`CaptionLayout{Mode,MaxCharsPerLine,MaxLines,MaxDurationUs,PauseThresholdUs}` 为可选持久字段。`NormalizeCaptionLayout` 返回独立规范副本：nil保留未指定（旧nil等价默认逐词），word归一为逐词模式；readable的零字段统一为每行18字符、2行、4秒和700毫秒停顿。范围分别为2–120字符、1–4行、0.1–60秒和不超过10秒的停顿阈值。仅 `generate_bound_captions` 命令接受布局字段，普通命令不能夹带；应用仍需拒绝前端任意源词/来源对象。

阅读组按真实时间顺序的连续词构成，遇到句末标点、实际停顿、说话人变化、重叠词、排除词、行数/行宽/时长上限时分组。停顿和持续时长按当前播放速度/有理数帧率判断，组区间取实际首词起点和末词终点的映射外包，不插值、不根据稿件估时。源移动、修剪、分割、复制和变速后重新派生，linked音画不重复；旧讲话换画面仍跟随真实音频承载，RawWords及来源不改。

中文不无条件加空格，英文词边界只补必要空格，实际已有空白和换行保留。换行优先已有词边界，不把英文单词拆开，避免关闭标点行首和单独标点卡；超长中文词条只允许排版换行，不拆它的时间。单条真实词时间对应文字或时长仍无法容纳时明确拒绝，要求增加上限，不能凭文字猜内部时间。字符宽度采用Unicode字符数，完整字体字形宽度、所有语言的排版与高级语义理解不在本轮承诺中。

手改文字、样式、Transform或展示轨的组作为保护边界，完整可见时保留ID及覆盖；模板上限不强制拆散人工文字组。已手改组新增裁断、删词、内插/重排词、说话人/时间冲突或无法保持手改布局时原子拒绝，提示调整切口或先解除绑定。既有部分词组可以在源窗口及可见帧完全不变时继续编辑或更换真实carrier，不会因重新保存文字误报新裁断。整组已经被剪出窗口或用户明确删除/解绑时，仍遵循原有删除/排除与Undo规则。逐词旧默认保留原切口部分词行为；多词模式不会静默把手改卡片改成无绑定静态字幕。

阅读模式改变的是自动组，不能保证所有人工保护组都会合并。跨说话人语义删句、自动缩写扩展、逐字符TTS时间对齐获取、样本级播放与完整阅读质量仍由其它模块/后续验收处理；这里没有任何模型调用。

## 当前边界与验证

每份转写最多 100000 个词条、每版文本 16MiB；工程最多 1000 份转写、原始与接受词总数最多 1000000；派生字幕最多 100000 条，复杂重叠需要整理。保存文件仍受 64MiB 上限约束。撤销历史仅在当前进程内保留，保存的是原始词、当前接受版本、绑定与覆盖，不是持久撤销日志。

## 精确音频源末端

全局时间线仍使用工程帧，画面范围/分割不改变。`Clip.AudioRange,omitempty` 为声音单独声明半开源区间：`{Unit:"us"|"samples",Start,End,SampleRate?,SourceOriginUs?,OffsetNum?,OffsetDen?}`。Offset单位为微秒分数，表示真实音频起点相对StartFrame的偏移；不能把音频强行延长至向上取整后的显示占位。

`Asset.AudioSampleRate`、`AudioSampleCount *int64` 和 `AudioStartUs` 保存媒体层实际测量的时钟。nil count表示未知，0是实测空；采样率已知不等于count已知。绝不通过DurationUs乘采样率伪造总样本数。samples区间内的采样率/原点副本必须匹配素材证据，End不能越过实测count。未知count仅能使用源微秒区间，不能标为实测samples。首样本原点须与Probe/Prepare一致，晚起音轨保留真实lead，不搬到0。

`AudioClipToSourceEnd(clip,asset,settings)` 显式选择入点之后的实际完整音频，优先实测samples，否则声明微秒末端；DurationFrames向上取整只用于显示。`ResolveAudioRange` 返回源和工程真实起止（`AudioTime{Num,Den}`，单位微秒，可Rat()）、样本端点与Empty标记。无AudioRange仍保持旧帧选区含义；完整导入必须显式调用helper，不能猜旧片段是用户裁剪还是旧导入。

精确split左右共享同一向上取整的源单位切口，右段保留分数起点偏移，直接左trim与split后删除左段相同。44.1/48kHz与29.97fps的共同边界可能不落在帧上；左段最后一个完整sample允许跨名义帧末不足1sample，真实左右仍严格相接，总样本数不变。递归切剪保存源锚点分数，不逐段丢弃微秒。处于真实音轨覆盖外的子段可以是显式Empty，不造音频或循环填满。

移动/复制保持真实末端，普通audio改速保留显式源选择并在未指定新显示长度时重新ceil；与视觉链接时按新画面窗口裁选实际声音，画面帧语义仍是原规则。声音轨冲突按真实有理数声音区间判断，ceil占位相交不等于声音重叠；真实重叠依然拒绝。字幕使用真实声音范围，不能把尾部无声占位当词；阅读组手改保护和锁轨仍有效。原视频作为audio carrier时使用原真实音轨、映射、音量和精确区间，不新建伪audio素材。

精确字段、实测count指针、范围及分数偏移在Snapshot/Undo/Redo/JSON快照深拷贝/持久化。旧schema=1未使用时全部省略。模型可表达精确值不意味着每种播放器/渲染器已经消费；未实现精确处理的媒体后端应明确拒绝，不可忽略字段后声称样本无损。

测试覆盖 29.97fps、源边界截断、修剪/变速/移动、分割和复制的覆盖继承、linked 去重、纠错、陈旧源、隐式锁轨失败原子性、深拷贝、解绑以及保存重开。没有以静态 SRT 或假识别服务替代转写绑定验收。

## 多片段原子命令

move_clips使用ClipIDs、FrameDelta、TrackDelta，delete_clips使用ClipIDs。显式ID必须非空、存在且唯一，最多100000；默认按LinkGroup展开一次，可用既有Linked策略关闭联动。批量命令不能夹带单片段替换或无关字段；删除不能传位移。原轨/目标轨锁定、范围、类型和最终碰撞均整体校验，失败不产生修订或部分结果。更新共用SourcePhase/AudioRange准备，绑定字幕随源reconcile而不双移，独立时间移动须先解绑。一次Apply批次仍为一个Undo单位，幂等/版本规则不变。

## 多片段构造

split_clips使用ClipIDs/AtFrame，仅切跨越切点的成员且至少有一个交点；默认LinkGroup展开，右半及完全位于切口后的成员归新组。duplicate_clips使用ClipIDs/AtFrame/TrackDelta?，有效源最早起点对齐目标，保留间距及效果，副本成独立组。绑定字幕随源派生，独立操作需先解绑。原分割/复制共享SourcePhase/AudioRange准备函数。内部inheritance.parents不接受JSON也不进入Project，供单次字幕reconcile继承明确父源及排除词。最终整体校验，一次Undo和幂等规则不变。

## 工程剪贴板

CaptureTimelineClipboard构造单份不可变片段/关联字幕快照及资源/转写证明，编码预算64MiB。ClipboardPasteCommand仅内部传递快照，外部只提供opaque标识；普通ApplyEdit与Agent计划不得注入paste_clips。临时父源及排除词通过inheritance交给统一reconcile，旧源不存在仍能继承手改；自动字幕跟随当前转写，独立字幕快照解除绑定。副本ID按请求命名空间生成，同请求重试与Undo/Redo保持身份。ClipboardPasteSelection只读取当前工程中的对应副本。跨工程和帧率变化不隐式转换。

## 同量修剪

trim_clips使用ClipIDs、Edge(start/end)、非零FrameDelta及IncludeLinked?。起点正数右移/缩短、负数延长，终点正数延长/负数缩短；另一端与轨道保持。默认联动去重，至少1帧，全部候选共用prepareClipUpdate再统一字幕/最终校验；绑定字幕只随源。精确音频末端ceil占位合法，已有静音占位可收短，视频载体以容器时长为显示边界但不扩真实样本。原子、版本、幂等与一次Undo规则不变。

v3阶段工程格式中，字体是font Asset、文字通过fontAssetId引用；逻辑引用、锁轨和人工字幕覆盖走原命令。v1/v2迁移与新字段拒绝由UpgradeProject负责，字体文件读取不进入核心。

## 2026-10-27 v5多序列

根保存活动序列，OtherSequences保存其它序列，各自独立时基、轨道、片段与源词接受版本，共享Assets和VisualAnalyses；SequenceOrder保持稳定次序。普通导航不占Undo/不清Redo；历史记录操作前后的序列上下文，使跨序列Undo/Redo回到对应编辑位置。ValidateProject检查全部序列及共享素材引用，纯路径修复可跨锁轨，元数据变化不能越过非当前锁轨。ActiveSequenceView为显式只读投影，不能创建完整Engine或保存文件。详见[规格](../../docs/specs/2026-10-27-多序列工程.md)。
