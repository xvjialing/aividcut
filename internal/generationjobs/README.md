# 生成任务的持久协调

该包连接已登记的工程参考图片、连接凭据租约、模型适配器和结果导入器。与本地导出队列分开保存，因为生成可能已经计费，不能将请求超时当作重新提交的理由。

## 接口和约束

- 可选 `EstimateInput` 只接受 CNY/USD 人为参考单价及每次请求/每张图片/每秒视频单位，最多六位小数。Go 用整数重算 `CostEstimate`，明确未知与零，不做汇率、实际账单或费用上限判断。估价与请求共同去重；无估价沿 v1 签名，有估价保存 v2 并在加载时重新计算。失败、取消、未知及原任务恢复仍保留快照，不进入供应商 Request/Recipe。见[费用参考规格](../../docs/specs/2026-10-27-生成费用参考快照.md)。

- `New(Options)`：在独立目录加载元数据，取得操作系统排他文件锁；不在启动时访问凭据或发送模型请求。
- `Submit(ctx, project, input)`：需要稳定请求 ID、明确连接/模型和 `consent=true`。先验证并保存 queued，再保存 submitting，随后才允许一次 Submit。
- 同 ID、同连接、同工程与请求内容返回已有任务；工程 revision 改变不产生第二次计费。相同 ID 不同内容、损坏的已有记录均拒绝当作新请求。
- 一个运行槽、最多8个活动任务、默认历史2000份；已收尾且不可恢复的终态可归档，归档区最多20000份、分页读取，启动只索引文件标识。归档释放默认名额，但媒体原路径不动、不释放媒体空间；原ID（含损坏归档）继续占位，须还原后再读取/复用，不会重新POST。unknown需先明确核对；等待/可恢复/运行/损坏默认记录不能归档。详见[归档规格](../../docs/specs/2026-10-28-生成任务历史归档.md)。
- `StopWaiting` 取消本机等待，不调用远端 Cancel。未开始提交的队列可确认为 cancelled；已经开始但无远端 ID 的不确定提交进入 unknown。
- `Resume` 仅查询原远端 ID，或导入已成功返回/已原子提交的本地结果。异步下载失败后重新 GET 原任务以刷新结果地址，不重新 POST。
- 已完整提交的本地结果优先核验恢复，不需要重新取得凭据或访问远端。任务写入暂时失败时保留恢复入口；修复存储后可继续原任务。
- 同步生成的返回字节不写入任务 JSON。若应用在结果提交前崩溃且服务没有可查询 ID，无法凭空恢复丢失字节；保持 unknown，并让用户核对服务记录。
- `AcknowledgeUnknown` 只记录用户核对，不改变远端状态。`MarkImported` 支持部分候选；应用界面仍需以当前工程资产计算导入状态，以正确反映撤销和工程切换。
- `Close` 取消等待，最多同步等 3 秒；`Done` 在全部 worker 完成并释放目录锁后关闭。上层数据目录锁必须保留到 Done。

任务只记录参数、配方、远端 ID 和本地结果元数据，不记录 API Key、内联媒体或带签名的下载 URL。生成成功表示结果已保存，加入工程素材库另由应用层验证并提交统一编辑命令；本包不直接改时间线。

## 当前验证

本地 fixture 覆盖：同 ID/并发/重开去重、明确生成动作、持久化失败先于网络、未知结果和损坏记录保留、排队及提交中取消、远端任务停止后重开只查询、部分候选导入、文件已提交但任务未提交时的恢复，以及第二进程实例拒绝共享写入。额外回归覆盖写入失败可再恢复、异步本地完整结果不依赖凭据、同步返回丢失后直接 unknown。

测试未访问真实凭据库或收费模型，不能证明供应商账号权限、收费、地区和真实生成质量已通过验收。

## 成功配方与人工核对上下文（2026-10-26）

CompletedRecipe只对有效成功、不可继续恢复的任务返回不可变配方深拷贝，不暴露临时下载地址或凭据。SubmitInput.Context为可选projectId/revision/sourceEpoch快照，由应用层取工程时核对；Manager仍使用请求/连接/工程作为任务签名，Context不改变已保存任务v1。父配方沿原Request/Recipe记录，应用层额外核对来源属于当前工程的成功任务。现有MCP另有独立scope/revision校验。
