# 剪切取样相位实施契约

日期：2026-10-25。范围：常规视频/音频的分割、缩短修剪、移动、复制及其字幕跟随；原生拉帧和 FFmpeg 导出共用处理来源。不改变工程帧网格，不接受来自模型的伪造转写。

## 已复现的问题

- 60fps 编号源在 29.97fps 工程仅分割第 1 帧，右段重新以 `-ss` 后首有效 PTS 为锚，会改变未删除画面的帧选择。
- 44.1kHz 源、12345µs 入点在多处切开后，源重采样末端和时间线末端各自 ceil，产生原来没有的零采样。
- 单纯保存 `SourceStart − TimelineStart × Speed` 连续常量不足以重建原处理的首帧、重采样和 atempo 状态。每段补零或延长源 End 不能修复这些不变量。

## 持久 DTO

`Clip.SourcePhase *SourcePhase, omitempty`：旧 nil 工程仍以当前片段定义一份隐式配方。首次需要派生时捕获，不能把历史 nil 猜成另一个完整素材选区。

```go
type SourcePhase struct {
    Recipe SourceRecipe `json:"recipe"`
    OffsetFrames int64 `json:"offsetFrames"`
}
type SourceRecipe struct {
    AssetID string `json:"assetId"`
    SourceFingerprint string `json:"sourceFingerprint,omitempty"`
    Kind string `json:"kind"`
    StartFrame int64 `json:"startFrame"`
    DurationFrames int64 `json:"durationFrames"`
    SourceInUs int64 `json:"sourceInUs"`
    SpeedNum int `json:"speedNum"`
    SpeedDen int `json:"speedDen"`
    FPSNum int `json:"fpsNum"`
    FPSDen int `json:"fpsDen"`
    AudioRange *AudioRange `json:"audioRange,omitempty"`
}
```

Recipe 是首次派生前的完整处理输入及原输出范围；不保存名称、音量、静音、Transform、LUT 或字幕文本。当前片段的这些人工属性仍实时生效。OffsetFrames 是当前片段在原处理输出里的起点，当前输出窗为 `[OffsetFrames, OffsetFrames+DurationFrames)`。Recipe.StartFrame 保留捕获时的合法工程锚；移动后的相对平移由纯函数返回，不会为参考原点引入负的实际片段起点。

有声 video 即使原 AudioRange=nil，也在捕获时把其当前帧选区 materialize 为真实采样或声明微秒范围，保留首解码覆盖差额，不从 duration 反推实测 count。当前片段同时得到该 AudioRange，使视频分割的原声和字幕也走同一条精确来源。无声视频不添加音频范围。

## 纯函数

- `CaptureSourcePhase(clip, asset, settings) (Clip,error)`：返回拥有独立深拷贝的完整片段；已有相位则验证并复制，没有相位则捕获当前输入。有声源补齐当前 AudioRange。
- `CloneSourcePhase(*SourcePhase) *SourcePhase`：深拷贝 recipe.AudioRange。
- `ValidateSourcePhase(clip, asset, settings) error`：检查同素材/指纹、原范围、速度、fps 和输出窗；不修改输入。
- `ResolveSourcePhase(clip, asset, settings) (ResolvedSourcePhase,error)`：nil 也返回当前隐式配方。`Root` 为原配方片段，`WindowStartFrame/WindowEndFrame` 为原处理输出窗，`TimelineShiftFrames = Current.StartFrame − Recipe.StartFrame − OffsetFrames`。

## 命令传播规则

- 分割、缩短修剪：先捕获原完整片段，再让两段继承同一 recipe，仅改变输出偏移/长度；真实 AudioRange 仍按共享源单位切口分割。左段保留稳定 ID，右段有新 ID，不改变未选片段。
- 直接左 trim 与 split 后删左必须取得相同画面及 PCM。递归分割累加原输出偏移，不能逐次截断微秒。
- 移动、复制：保留 recipe/输出窗，平移放置；源处理状态不从派生段重新开始。复制子范围显式继承父配方。
- 显式 slip、更换素材、速度变化：按修改后的真实输入重建配方，不继续借用不匹配旧 recipe。超出原输出范围的延长 trim 也重建新范围，其它兄弟派生段不被改写。
- 仅修改音量、静音、Transform、LUT、名称：保留 phase。替换画面时视觉配方重建；原讲话的实际 audio carrier 继续继承原音频配方。
- 锁轨、隐式字幕变化、linkGroup 批次仍由同一原子命令/Undo/Redo 约束；phase 不扩张普通 ApplyEdit 的转写权限。

## 消费规则

视频先按 recipe 原 SourceInUs 取得首有效真实 PTS，以原速度和 fps 成立完整输出，再选择输出 frame window。不得对每个派生段重新 `-ss/setpts/fps`。VFR 按实际 PTS，手机 display matrix 在 fit 之前处理，与用户 Transform 分开。

音频先按 recipe 原完整源区间重建重采样和 atempo；派生片段只读取该原处理输出对应的共享窗口。当前 AudioRange 保留真实源单位切口，派生有效声音由原配方实际起止平移后与当前输出帧窗相交；首段保留原首端、末段保留原音尾，不能将每个源量化差额分别平移后制造重叠。PCM 输出端点只在最后按全局采样时钟 ceil。原处理输出参考起点可随移动落到工程零点以前，但实际声音窗口不得为负。不能在派生源 End 独立截断原处理器，否则重采样/atempo 的尾和状态再次改变。

原生解码器惰开；同一 recipe/放置相位可共享有界处理状态，离开活跃范围后释放。atempo 任意回跳若需重放从原配方起点重建并丢弃前缀，记录实际耗时，受进程请求 ctx/解码预算取消；不预渲染或缓存整段。

## 验收

必须覆盖 44.1/48kHz，非帧入点，多切点 1/2/5/10/20/30/40/50，0.5/1.5 倍速 whole 与 joined PCM，CFR/VFR whole 与 joined 编号画面，直接 trim=split删左，移动/复制、保存重开、Undo/Redo、锁轨和人工字幕保留。大分母采样时间用实际 header 与精确有理参考/消毒器验证。每次失败保留复现，不用静音、近似工程帧或“旧导出也这样”替代修复。
