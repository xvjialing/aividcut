# 实际依赖声明与产物绑定

签名边界：原文在签名前进入资源目录，inventory中的输入SHA属于收集时刻。签名后在材料目录外另写最终可执行文件/材料树绑定，先重核原文，禁止绑定覆盖程序或材料，避免签名和清单互相引用。后续重签名/改材料须重新绑定；文件完整绑定仍不代表许可批准。

2026-10-27，FW-R11/FW-R14/FW-R16，P0/P5。补齐可重复生成的应用依赖材料，不把去符号、文件存在或静态检查当作许可批准。原媒体SDK源码/许可、签名与Windows实机门槛保留。

Vite构建插件从generateBundle最终输出收集实际保留的npm模块，与lockfile v3/安装元信息核对；识别Vite/Rolldown生成的运行时helper。输出只有公开包名/版本/锁路径、字节量、相对JS/CSS文件及SHA，不输出开发机绝对路径、自有源码模块名或source map。后置钩子确保import preload等最终修改已完成，production测试核对真实embed.FS中的文件，不只检查另一个dist副本。

Python收集器只读取明确Go产物的go version -m -json和已有模块缓存，绑定实际版本/sum与产物SHA；检查时GOTOOLCHAIN=local/GOPROXY=off/GOSUMDB=off，不下载/执行包脚本。收集Go模块、实际npm包及匹配VERSION的Go工具链顶层LICENSE/COPYING/NOTICE/COPYRIGHT/AUTHORS/PATENTS原文本。单文件2MiB、总量64MiB、单依赖32文本、根目录4096条目；链接、特殊文件、越界/版本/hash变化拒绝，不复制同名源码文件。

缺失文本明确留issues，不从元数据表达式拼造MIT/GPL或自动认定商业许可。精确版本补充文本需维护组件ID、提交、URL、原SHA并在收集前核对，未知/额外版本不混入。缓存sum/integrity是绑定元数据，未替代逐文件发布归档验证；模块顶层声明不覆盖全部内嵌/文件级例外。

新目录才可生成，失败不能写出完整inventory成功声明。客户端构建自动在签名前将THIRD_PARTY_APPLICATION_NOTICES放入Mac资源或Windows随包目录；构建增加Python3.9+，运行客户端不需要Python。最终包保留原媒体许可材料，应用声明不能替代媒体闭包。licenseApproval始终false，缺项仍随候选交接。

验收包括实际前端包与生成helper、最终JS/CSS/嵌入哈希、实际Go双端模块差异、原文/补充原文/专利声明、缺失不补造、版本/hash/链接/越界/产物变化拒绝、源码路径不进入清单、默认构建集成、双端产物及文档追踪。工具不进入编辑核心，不改变工程或模型调用。

依据：[Vite插件钩子](https://vite.dev/guide/api-plugin)、[npm锁文件](https://docs.npmjs.com/files/package-lock.json/)与当前Go help version/runtime debug.BuildInfo；来源核查日期2026-10-27。
