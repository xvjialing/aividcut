# 音频剪切资源与混音实施范围

日期：2026-10-25。关联 FW-R01、FW-R15；沿用原处理配方的样本不变量，P0/P1 尚未完成。

先生成无用户内容的真实连续音轨，分别记录整段和核心实际切为64段的加载、顺序拉帧、定位、RSS及声音输出。使用同SDK、同输入/分辨率/帧率、明确旧新worker指纹，不把分配的虚拟容量等同实测RSS。

本项目的受控音轨均已归一为48kHz、双声道、交错float32和共同全局样本区间。专用混音只做逐样本相加，保留输入音量、静音、真实首尾与半开范围；遇到格式、时钟或样本长度不符必须拒绝，不能取较短长度、重启相位或增加静音来掩盖错误。不承诺继承通用mix的ducking/crossfade功能，新增这些用户能力需独立契约。

混音不得按每个派生片段分配固定多秒PCM。处理状态惰开、有界、失活释放；原配方相同的派生段共享处理时必须把素材身份、完整源范围、速度及放置相位纳入身份，不混淆独立片段或不同文件。随机回跳重建原处理输入仍受取消与时间预算约束。

必须验证两条不同频率声音的求和、音量与静音、仅音频/黑画面、轨道间空洞、单帧段、29.97fps、44.1→48k、倍速、多切点、向前/后Seek与重新Load。whole/split PCM不变是必要条件，不能只用性能数据通过。检查损坏源报错后进程存活和ASan/UBSan；Windows原生与完整进程树仍单独验收。

纯画面Preview入口须Samples=0且显式pictureOnly，不能进入播放声音队列；完整Seek保留，后续Next在同一目标恢复真实PCM。格式回归覆盖MP3部分skip的包时间基及AAC负PTS priming；参考先按首有效源样本计数归零后重采样。
