# 实时编辑效果与预缓冲

日期：2026-10-25。关联 FW-R01、FW-R05、FW-R06、FW-R11、FW-R15、FW-R17。状态：实施中，以下是本轮要证明的范围；未通过的项目不能仅因代码或接口存在标为完成。

## 当前问题与目标

上一轮已跑通常驻媒体、二进制背压、Canvas 与音频主时钟，但变速、旋转、部分 LUT 强度和分数声音偏移仍被原生编译器拒绝。这会使正常手工编辑后的工程无法继续实时检查。本轮目标是让这些操作沿同一工程状态与预览链路工作，并保留已有撤销、字幕与导出语义。

播放 reset 目前立即开始消费，首个实际包到达前会累计欠载。本轮增加真实 PCM 预缓冲及欠载恢复；不能只把等待计数改名，或者用计时器/虚构静音推进内容位置。

## 时间与声音约束

- 接受工程既有速度范围和有理数速度，保持现有导出 atempo 的音高语义。实际源入点、起点、源末端和时间线末端分别核对。
- `AudioRange` 的 samples/us、正负与分数 offset 均通过 `ResolveAudioRange` 解释。负偏移可能早于视觉片段起点，不能在视觉 playlist 内门控后仍丢掉早起部分。
- 输出固定 48kHz stereo；每帧端点按工程有理数帧率换算至输出样本时钟，样本区间连续，29.97fps 切口不逐次丢样本。
- 声音处理流式、有界并尽量懒开解码器；不为支持变速而预渲染整个工程或将整段 PCM 长驻内存。
- Seek 后不能沿用前一位置的滤镜残余；正确性需要与从头播放到目标位置的结果比较。为重建相位所需的前置解码成本、取消和限制须如实记录。
- 保留晚起音轨、非零 format 起点、44.1/48kHz、短尾、分割、不同速度和源入点的真实回归。

## 画面与 LUT 约束

图像按当前导出的顺序处理：源裁剪/速度、画幅适配、缩放、旋转、LUT 与强度混合、平移及轨道合成。具体算子与现有渲染器核对后实施，不以名称相同推导结果相同。

旋转方向、中心、扩展边界、透明区域和缩放取整须用非对称图案验证。LUT 保留已验证 3D cube 的域、插值与强度语义，覆盖 0/.25/.5/1 和带 alpha 素材；不能把强度改成全片透明度。

优先复用实际 SDK 的同源处理算子。需要新增自有 MLT 服务时，只接收 Go 受控编译器产生的固定属性，不开放用户任意 filtergraph 或外部 XML。

## 前端缓冲约束

保留最多 3 包与真实消费后 ACK。启动先累计真实 PCM；达到目标、已接收尾包或已经达到包数上限时开始，防止单包短工程和高帧率工程永久等不到阈值。

真正耗尽时内容时钟保持，待足够连续真实 PCM 后恢复。startup 等待与运行欠载分别报告，不删除已经发生的欠载证据。暂停、快速定位、epoch 更换、隐藏窗口、错误与销毁均清理旧队列；尾 PCM 消费后才到 exclusive end。

状态继续位于画面外，正常缓冲、失败原因和恢复操作可见；不能以恢复播放为由覆盖用户的暂停意图。

## 验证与资源诊断

1. 自建非对称 RGBA、透明图片和变换 cube，与现有 FFmpeg 实际输出核对关键几何、色值、alpha 和轨道顺序。
2. 自建运动视频和不同音调，验证 0.5/1.5/2 倍及非整数源入点、分割/修剪/偏移后音画对应与真实样本。
3. 实际 AudioWorklet 模块验证启动、单包尾、高低帧率、欠载、恢复、暂停和旧 epoch；再用真实 Go/MLT/浏览器复验。
4. 提供可复现的原生拉帧诊断命令，记录实际输入、输出、加载/定位/拉帧延迟及采样 RSS；原生吞吐与设备播放、整个桌面进程树分别标示，不以无节奏拉帧等同实时体验。
5. 双端编译、当前真实媒体回归、文档追踪与来源记录继续保留。Windows 原生、完整字体色彩、GPU、长素材和发行许可仍有独立门槛。
