# 实时预览与精确音频区间

日期：2026-10-25。关联 FW-R01、FW-R03、FW-R05、FW-R06、FW-R11、FW-R14、FW-R15、FW-R17。本规格记录本轮已实施的协议及仍受限的范围，不表示 P0 整体完成。

## 工程音频时钟

时间线位置仍以整数工程帧表达；实际声音可在一帧内部结束。不能为迁就画面帧，把音频末端向下取整后丢掉剩余样本。

Asset 增加可选 `audioSampleRate`、`audioSampleCount` 和 `audioStartUs`。count 缺失表示未知，零表示实际观测为空；不得使用容器 duration×rate 冒充实际计数。样本零的源时钟锚以整数微秒记录，样本长度仍保持 count/rate。源时间原点与 FFmpeg 准备/渲染链路一致，MOV 的 format 起点和音轨晚起分别处理。

Clip 的可选 `audioRange` 是源音轨半开区间：

| 字段 | 含义 |
| --- | --- |
| unit | `us` 或 `samples` |
| start/end | 源区间，不包含 end |
| sampleRate/sourceOriginUs | 样本区间时钟副本，必须匹配 Asset 的实际证据 |
| offsetNum/offsetDen | 相对片段 StartFrame 的分数微秒偏移，领域层支持正负偏移 |

旧工程未提供 audioRange 时保留原帧语义。`ResolveAudioRange` 统一解析，`AudioClipToSourceEnd` 统一构造完整源音尾：显示占位向上取整，声音在真实末端停止。采样证据在复制、分割、修剪、移动、变速、字幕映射、Undo/Redo 和保存重开时保持一致。

分割使用共享源切口与分数偏移，防止两侧重复/漏样本；多次分割不能逐次累积整微秒舍入误差。输出音频按输出样本时钟裁断；同源分割片段共享解码/重采样后再分支，避免每段重置重采样相位。AAC 有损编码的 padding、振铃与 PCM 区间语义分别验收。

## 实际计数及普通上轨

`Toolchain.MeasureAudioSamples` 逐解码帧累加实际 nb_samples，同时校验采样率、声道、顺序和 PTS 连续性。它处理可证明的时间基量化误差，拒绝内部缺口/重叠，支持调用方取消并检查读取期间文件身份。普通导入在绑定样本证据后再次核对源内容 SHA，避免 Probe 与计数恰好读取了不同内容。

普通导入自动计数目前限每文件 5 分钟、128MiB，单批累计 10 分钟、共用 15 秒预算。同批相同路径不会重复扫描；用户取消中止本次导入。超限/预算耗尽或仅有 ffprobe 时保留未知 count，返回 `Bootstrap.warnings`。真实时间不连续或内容变化不作为成功计数。当前尚无超限素材的惰性补测界面。

warnings 是本次操作的非持久提示，工程文件不保存它。界面可展开完整中文原因；新 Bootstrap 未提供或给出空数组时清除旧提示。未知 count 的音频仍可按声明微秒末端上轨，但必须明确精度边界。

`AddAudioToTimeline({projectId,projectRevision,assetId,clipId,startFrame,trackId?})` 接受已登记素材，通过核心 helper 构造片段。自动找轨按真实声音区间判断重叠；显式轨道继续验证锁轨和重叠。稳定 clipId 用于重试，已有相同片段不会重复添加；相同 ID 的不同内容/明确不同轨道被拒绝。Undo 后的过期请求不能重建已撤销片段。配音与工作流沿用相同领域规则。

## 媒体进程及应用接口

MLT worker 是常驻独立进程，Go 顺序执行 Load/Seek/Next 等操作。Start 的 context 表示会话寿命，不能使用 HTTP 响应结束即取消的 request context。单次操作另有 context；已经开始的操作取消/超时会结束该进程，不能继续复用可能乱序的管道。

| 应用方法 | 职责 |
| --- | --- |
| GetPlaybackCapabilities | 核对插件和当前工程，实际字体测量/建图成功后才报告工程可用 |
| StartPlayback | 核对工程 ID/revision，加载并真实拉取定位帧后返回临时连接 |
| ControlPlayback | 串行 play/pause/seek，可携音频主时钟的整数帧位置 |
| GetPlaybackStatus | 返回当前会话状态，不返回令牌或连接地址 |
| StopPlayback | 取消当前会话、关闭连接并释放 worker |

加载与替换串行且可取消排队。旧 worker 的 Close 返回并不等于已退出，必须等 Done；超时明确报告仍在释放，不能启动第二个实例。加载失败的未提交 worker 也遵守该条件。能力查询最多一个短检查进程，排队的过期工程版本不再启动建图。

普通启动不启动播放 worker。配置只接收明确的 worker/repository/profiles；`make native-worker` 从显式 SDK 构建本项目二进制及开发 symlink，完整成功后才写标记。`make dev` 可复用这一组已生成路径，显式环境变量优先。打包第三方媒体库是后续独立交付工作。

## 二进制、背压和音频主时钟

worker→Go 与 Go→WebSocket 使用 AIV1。每包先传 16 字节头：4 字节 magic、JSON/RGBA/PCM 三个 uint32BE 长度，再传三段内容。JSON 上限 128KiB，RGBA 上限 1920×1080×4，PCM 上限 1MiB；逐段写出，避免 JSON/Base64 逐帧搬运。插件 stdout 转入有界 stderr，不得污染协议。

图像为 packed RGBA8；声音为 48kHz、双声道、交错小端 float32。实际每帧 samples 和 audioStartSample 来自 MLT 输出时钟，29.97fps 不能使用固定 1600 样本替代。Go 核对定位结果、帧序与音频样本连续性，异常先停止，不向设备继续发坏帧。

WebSocket 只绑定随机回环端口，使用临时随机令牌并核对 Host、Origin、路径与参数。连接地址仅存于播放器内存；不能进入工程、普通状态或日志。单会话一个连接。工程实例或 revision 变化使旧会话失效，即使重开同 ID 工程也不复用旧图。

每次播放、暂停、定位更换 epoch，状态先于对应帧发送。最多 3 个未确认数据包；前端只有在 PCM 真正消费且画面已显示或明确丢弃后，才连续 ACK。暂停快照只绘图、丢弃声音并立即确认；Seek 不消耗媒体游标，随后 Next 从相同目标帧开始，避免重复目标帧音频。

Canvas 绘图与音频设备由独立模块管理，React 不持有逐帧画面。AudioWorklet 实际消费的 PCM 推进内容时钟；欠载输出静音时内容位置保持。requestAnimationFrame 只安排画面，不充当内容时钟。尾帧的 PCM 消费结束后，播放头到 exclusive durationFrames。

音频设备必须实际提供 48kHz，WebView 必须能加载静态 Worklet 或受控 Blob 模块。缺能力显示具体原因，失败模式不回退到假时钟。切换模式清理旧 HTML 音频，选中源素材时也停止工程声音，防止重复混音。暂停/定位当前以工程帧为单位，可能重播不足一帧的声音，尚非采样级随机定位。

## 原生范围与验收边界

本轮支持受控图片/视频、音频混合、基础平移缩放、实验文字、全强度 LUT 的已验证子集；最长 24 小时、最多 128 片段、4K 源像素上限、2–120fps。默认预览代理上限 1280×720，不改变工程坐标。旋转、变速、部分 LUT 强度及非零 AudioRange 子帧 offset 等尚未通过原生实现，按实际工程明确拒绝。

qtext 使用纯文字分支，清空 HTML/resource；实际 Qt 字形测量阻止超框自动缩字。晚起音轨通过实际首有效解码帧 PTS 和 format 起点，在混音前保留应有的静音及源波形相位。上述子集不代表字体、色彩、导出、GPU、长素材资源和 Windows 已全面一致。

实际样本、设备结果、失败处理及未完成项见[本轮验收](../implementation/2026-10-25-实时预览与采样音尾验收.md)。
