# 本地 Agent 应用接口

日期：2026-10-25。状态：实施中。关联 FW-R02/FW-R07/FW-R08/FW-R11/FW-R16/FW-R17。本轮连接结构化计划，不自动运行登录或收费推理；MCP、ASR、语音生成及完整工作流另按原路线推进。

## 接口

- `GetAgentStatus()` → `localagent.Installation[]`。显式检测本机安装、独立作用域登录与分项隔离状态，不把已安装等同于可以规划。
- `GetAgentLoginInstructions(provider)` → `{executable,args,environment,notice}`。仅展示 CLI 正常登录的参数和环境，由用户手动操作；界面不拼接执行 shell。
- `GetAgentWorkflows()` → `{id,name,description,available,reason}[]`，按工程当前素材与前置数据说明。
- `StartAgentPlan({id,provider,instruction,workflow,selection,consent})` → AgentJob。仅明确调用所选 CLI 后传 consent=true，提示可能使用账户额度。
- `ListAgentPlans()` → AgentJob[]。
- `CancelAgentPlan(id)` → AgentJob，停止本机等待和子进程，不自动应用结果。
- `ApplyAgentPlan(id)` → Bootstrap，显式一次性提交，支持统一撤销。

```typescript
type AgentJob = {
  id: string;
  provider: 'codex' | 'claude';
  projectId: string;
  projectRevision: number;
  status: 'queued' | 'running' | 'succeeded' | 'failed' | 'cancelling' | 'cancelled';
  message: string;
  createdAt: string;
  updatedAt: string;
  result?: {
    provider: 'codex' | 'claude';
    request: EditRequest;
    coreValidated: boolean;
    warnings: string[];
  };
  applied: boolean;
};
```

## 状态和工程约束

先保存请求标识和工程指纹，再启动有界本地队列；相同请求 ID/工程/内容返回已有任务，不再次调用 CLI。不同内容复用 ID 拒绝。重开后中断任务显示失败和核对说明，不自动恢复推理。最多 1000 份记录、16MiB 资料，历史归档界面尚未提供。

计划先在工程副本校验，应用时再次验证原工程 ID、revision、内容指纹、选区、链接和锁轨。计划不导入任意素材、不解除锁轨或修改时基。应用后保持同一计划的已应用历史标志；Undo 不会使同 ID 自动执行第二次，继续修改需基于当前工程生成新计划。

计划完成不代表已经修改时间线。界面显示结构化操作摘要和受影响片段，用户通过“应用计划”提交；旧工程或旧 revision 禁止提交。错误保留工程和已有计划，不能伪造 CLI 成功。

本地状态目录保存非认证的请求/计划元数据；CLI 认证仍由 CLI 自身管理。CLI 使用独立正常登录作用域，不读取或复制其他作用域的 auth 文件。临时规划目录和进程锁保留到 worker 结束后才释放。

## 当前边界

Codex 只对已核对版本和独立作用域开放条件可用状态；实际账户需用户正常登录并重新检查。本机之前检测为 needs_login。Claude 的策略 hooks 和 Windows 进程树仍待验证，界面展示原因，不作成功降级。四个业务工作流的前置分析、语音和生成集成仍未全部完成，不能将可见工作流名称当作全流程已实现。
