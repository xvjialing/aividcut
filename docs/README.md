## 使用与更新

用户后续明确要求优先于已有建议。已确认需求和已记录的正式决策构成当前实施依据；技术建议需要通过原型或评审形成决策。历史快照用于追溯，不自动覆盖活动文档。

开始一个阶段：确认需求编号 → 读取当前决策 → 写具体范围和验收 → 实施与验证 → 更新阶段状态和矩阵 → 记录差异。不因文档中出现了某个模型名或框架名就把它标记为已实现。

原始竞品与模型研究沿用原报告日期；2026-10-24 新增官方资料核查的桌面技术栈评估，仍未进行性能对照测试。来源清单见 [参考资料](research/参考资料.md)，原文见 [完整规划快照](archive/2026-10-24-竞品调研与实现规划-v0.2.md)。
