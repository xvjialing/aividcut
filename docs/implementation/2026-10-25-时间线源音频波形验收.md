# 时间线源音频波形验收

日期：2026-10-25。需求：FW-R01、FW-R12、FW-R15。依据：[波形规格](../specs/2026-10-25-时间线源音频波形.md)。状态：增加真实源波形及局部验收，P0/P1 整体仍在进行。

## 本轮实现

音频片段与有声视频共用 `ClipWaveform`。真实源音频按4秒窗口流式解码，每桶约10ms，保留全部声道的正负极值及实际样本数；反相双声道不会因下混而变成假静音。前端只接收包络，不加载整条PCM；画布仅分配当前可见的声音覆盖，设备像素比最多2。

片段显示按源区间、速度、音频样本原点和分数offset映射。修剪起点临时平移已读取包络，提交后读取扩展出的源区；分割、修剪、撤销及重开继续使用既有工程核心。波形为源素材的峰值参考，不是音量、音效、atempo或最终混音后的输出，也不是响度或语音检测。

Go应用接口只接受当前工程、登记素材、源指纹和窗口编号，不接受前端任意路径；读取前后验证文件身份、大小和修改时间。后端最多2个提取器、128个等待分块与128个完成缓存；前端共享在途请求，每个可见片段顺序取块。最后订阅者离开会取消；切换工程和关闭会取消旧读取并等待提取结束。取消标识保留短期墓碑，处理取消早于读取注册的到达顺序。

现有22px片段下部容纳波形、加载和重试状态，名称、选择及修剪把手位置稳定。缺失源不显示示例数据，失败不阻止普通编辑。已选片段不重复执行选择导航，把手点击后保留焦点供方向键修剪。时间线公共容器处理纵向滚轮，保留Shift/横向及Ctrl/Meta手势的原有用途。

## 真实音频证据

媒体工具为显式配置的独立 FFmpeg/ffprobe，本机版本9.0.2；未读取其他剪辑软件的二进制。WAV由测试直接写出样本，压缩格式再由本机编码器生成。

| 场景 | 结果 |
| --- | --- |
| 48kHz、192000+5777样本、已知脉冲及静音 | 两窗计数192000与5777，尾窗13桶，最后17样本；极值与写入样本对应 |
| 反相双声道 | 首桶正负极值为±0.75，没有下混抵消 |
| 44.1kHz MP3首/中/尾窗 | 176400、176400、44177样本；与独立整段解码的逐桶峰值最大误差均0 |
| 同源AAC首/中/尾窗 | 样本数同上；峰值最大误差分别0、0.0005693436、0.0014278814，在预设0.002满幅包络容差内；不声称逐样本相等 |
| 0.5秒晚起、容器起点3秒的MOV | 波形源起点500000µs，首窗154350样本，未补造前静音；远窗从4秒读取 |
| 内部100ms时钟缺口 | 明确拒绝，未把缺口压缩成连续波形 |

测试暴露并修复两种寻址问题：远窗直接seek会破坏MP3储备及AAC开头状态，现先预卷1秒，再按目标PTS裁切；首窗显式 `-ss 0` 会丢失AAC负PTS预热包，现从容器头直接读取。逐帧时钟核查保留不超过1ms的容器量化容差。

缓存/队列测试覆盖共享、最后订阅取消、并发上限2、等待上限128、缓存上限128、结果副本、源变化、读取中变化与关闭。应用测试证明工程/指纹失配拒绝、先到取消有效，以及读取不修改revision、dirty或撤销历史。

## 限制与继续方向

本轮独立浏览器服务只配置FFmpeg/ffprobe，未将波形验收冒充MLT实时音画同步验证。新波形在Wails原生窗口与Windows实机仍待操作验收；此前原生窗口保留，未强制退出或绕过系统锁屏。

目前支持8–192kHz、1–8声道和24小时内的源窗。固定10ms包络不是样本级放大编辑；AAC远窗存在上述小幅峰值差异。文件stat失效机制不是每次全文件重新做密码学核验；外部改写文件但保留全部文件身份、大小和时间属性不能据此保证检测。没有全源多分辨率持久波形索引，首次远区仍有解码成本，尚未量测长自然素材下完整进程树和持续滚动资源。

生产主块约515kB，保留超过500kB的构建提示；没有为通过校验隐藏提示。离开视区时释放画布后备存储，重新进入后读取并绘制；完整大工程、纵向轨道虚拟化、GPU、正式媒体SDK/字体/许可分发、双端原生及真实模型/CLI账号质量仍未完成。本轮不解除P0/P1或商业发布门槛，继续按原路线图推进完整目标。
