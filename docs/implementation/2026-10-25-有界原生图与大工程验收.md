# 有界原生图与大工程验收

日期：2026-10-25。关联FW-R01、FW-R15、FW-R17，依据[有界原生图规格](../specs/2026-10-25-有界原生播放图.md)。状态：新增大工程窗口和局部验收，完整P0/P1与商业交付仍未完成。

## 实现与约束

此前编译器为每个片段建立独立MLT轨道，并拒绝全工程超过128片段。现在对较大工程保存独立快照、建立活动区间树，在Next/Seek/Preview前加载当前位置所需的有界图。默认优先32个相交片段、最长约8秒；实际同时有效片段更多时提升预算，硬上界128。密集剪切缩短窗口，长空隙保持空隙，不把后续片段移到开头。

128片段以内默认保留原图，旧worker仍执行原来的限制。较大工程需要worker明确声明windowedGraph能力和受控重采样后端；不支持时拒绝，不静默遗漏后段。完整索引限制100000片段，图仍限制3MiB/XML、4MiB控制包与既有画面资源预算。这个索引上界不是已验收容量。

所有片段先做核心和原生语义验证，文字逐条实际测量，初次加载预检所有已登记使用源。活动范围同时包含可见画面和真实声音区间向帧的外扩，避免负子帧偏移或声音末端被显示帧边界裁掉。隐藏、静音等状态沿用原语义。

窗口保留工程绝对帧、完整处理配方、源指纹/放置相位、全局样本钟和duration。替换图保留playing与下一拉取游标，源音视频缓存继续复用；新工程Load清空缓存。Go把已返回帧与下一Next位置分开，替换确认不匹配或失败时停止会话。手动、Agent和工作流共用的工程及撤销没有改变。

## 生命周期问题与修复

首次10000静态图片段测试虽然能完成，但采样worker RSS达到164462592字节，并随替换次数增长。清理MLT空闲pool没有改善，未保留该做法。

随后通过公开MLT API挂接属性销毁标记，区分图根、producer和服务属性寿命。1000片段结束时图根仅1个，但resample标记2033个，其他自动滤镜约17个，新增回归因此失败。官方[filter基类释放实现](https://raw.githubusercontent.com/mltframework/mlt/master/src/framework/mlt_filter.c)与[resample实现](https://raw.githubusercontent.com/mltframework/mlt/master/src/modules/resample/filter_resample.c)支持定位：该自定义close清理私有数据却没有完整清理父service；本机运行证据与之吻合。

worker现在在具备swresample时，将自身仓库中的自动resample工厂统一到现有FFmpeg swresample后端。不修改系统库，不直接调整私有引用计数，也不复制第三方实现。受控声音仍由自己的48kHz处理链输出；真实PCM和画面校验值未变。缺少swresample时不声明大工程窗口能力。

修复后的10000图片段采样RSS为57131008字节，存活标记为图根1、producer162、服务910；resample标记降为当前图的65个，不再累积旧窗口。标记统计覆盖公开可达对象的属性寿命，不等同于全部原生堆或独占内存。

## 固定负载结果

机器为Apple M5 Pro、18逻辑CPU、48GiB，macOS26.6.2；Go1.27、MLT7.42.0、独立FFmpeg9.0.2。源文件均本工程自建，无用户素材或其他剪辑器二进制。测量由preview-benchmark连续pull、流式CRC和对明确PID的ps定时采样组成；没有声卡、真实播放节奏或完整进程树测量。内存为采样RSS，不能作为精确峰值或各进程独占内存求和。

前两行同一个已保存工程和诊断程序，仅窗口参数不同，RGBA CRC1913617225、PCM CRC1807211711一致，用于选择窗口目标。最终10000图包含333次加载/332次替换，最大XML40023字节，RGBA CRC1579467295、PCM CRC2182089413；静态图没有真实声音，PCM为静音。

音轨的完整版本与1000切片版本PCM CRC均1738377043，RGBA CRC3445617415；实际解码器打开1次、音频处理图建立1次，最大队列52573采样帧。视频的完整版本与1000切片版本RGBA CRC均3155604016、PCM CRC1820249527；解码器和取样原点复用的回归另有明确计数。该编号视频没有声音，不能把它的静音PCM当作音质证据。

图片为320×180工程中的静态自建格图，每段1帧；视频为60fps编码格、实际B帧/固定120帧GOP、60→29.97、12345µs入点。它们验证图调度、帧时钟和已知负载，不代表自然摄影复杂度、任意叠加轨数、GPU或所有设备实时能力。整段视频本身p95约4.493ms，1000切片最终为5.344ms；不声称分割比未分割更快。

原始工程、报告与过程对照位于work/graph-window-*；可长期查阅的精简证据见[JSON记录](evidence/2026-10-25-有界原生图.json)。工具新增-window-clips/-window-frames用于收紧预算对照。音视频夹具通过单个真实核心事务逆序分割，避免负载生成时保存上万份撤销历史；原始用户工程不受影响。
