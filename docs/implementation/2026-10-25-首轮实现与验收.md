## 2. 真实后端流程

`scripts/smoke_backend.py` 通过同一 Go 应用层执行真实 HTTP 操作，不使用假工程或生成服务 mock。首次完整运行通过 14 项：

1. 真实音视频和 LUT 导入。
2. 素材 Range 读取。
3. 重复请求不重复剪辑。
4. 分割后的源入点保持。
5. 锁轨拒绝编辑且无部分提交。
6. 重叠字幕完整分轨。
7. SRT 导出不丢文字。
8. 保存后的 dirty 状态准确。
9. 字幕整批撤销。
10. 重做回到已保存内容。
11. 新建后重开原工程，数据完整。
12. 真实 1920×1080 合成帧及修订号。
13. 导出任务提交实际文件。
14. 输出 1280×720、约 4.5 秒且包含音频。

本机证据在 `work/e2e/smoke-rvf49tn3/evidence.json`，工程、合成 PNG 与导出 MP4 在同一目录。脚本可在独立开发服务重跑；检测到非验证工程的未保存内容时会停止，以免覆盖。

## 3. 原生与浏览器观察

macOS Wails 窗口中，已通过系统选择器导入 `work/e2e/clip-a.mp4`、双击上轨、Space 播放及 Cmd+S 保存。实际工程文件为 `work/e2e/native-20261025.aividcut`。

新版窗口验证了：输入工程名称而不失焦，Cmd+Q 后先提交草稿、刷新权威状态，再出现“关闭前保存工程？”对话框；窗口未直接退出，说明该边界没有仅依靠旧 dirty 状态。

浏览器连接真实 Go 服务验证了工程名称提交、未保存更改确认，以及键盘定位到片段内部、分割后增加片段、撤销恢复原数量。开发期间持续修改 hooks 曾触发 Fast Refresh 错误，冻结源码后全量重载再做验证；不把热更新期间现象直接记为生产缺陷，也不据此跳过最终检查。

工作区的 HTML 媒体/文字展示与 Go 合成检查有明确区别：LUT 与最终文字输出需使用合成帧核对。`nativePlayback` 始终为 false，不将浏览器多元素同步或离线 FFmpeg 当作原生实时引擎已通过。

## 4. 构建和测试证据边界

- `scripts/build.sh` 已生成 macOS arm64 `.app`，版本 0.1.0、声明最低 macOS 13.0；这不是对全部旧系统的兼容承诺。
- Windows AMD64 交叉编译产物位于 `work/build/AIVidCut.exe`，只证明源码/依赖可编译，不证明 Windows 预览、输入、安装和更新已验收。
- 各模块实际命令和限制保存在测试及包内说明；生成模块以本地 HTTP fixtures 验证协议和安全边界，没有真实收费调用。
- 静态 UI 审计、设计文档 lint、类型与构建通过，不代替真实键盘、焦点、输入法和媒体性能结果。

最终整合测试结果会继续补充，不能照抄旧缓存或子任务结果作为全部软件完成证据。

## 5. 工具与发行约束

产品仅使用显式配置或 PATH 中的 FFmpeg/ffprobe，不扫描或依赖其他应用目录。本机开发实测调用了已安装的工具，没有将其复制进应用包；相应构建包含 GPL/nonfree 选项，不能据此认定可作为本产品商业发行物。

系统字体只用于本机验证，没有打包再分发。正式媒体工具、字体、编码器与依赖的选择仍需核查。当前导出支持 MP4 和已声明的效果；不支持的文字变换或工具能力会明确报错。

安全提交按平台使用无覆盖操作及受控回退，取消与失败保护既有输出；Windows/exFAT 的分支测试与交叉编译仍不能冒充相应设备实测。
