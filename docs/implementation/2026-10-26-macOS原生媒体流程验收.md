# macOS原生媒体流程验收

日期：2026-10-26。关联FW-R01/FW-R10/FW-R12/FW-R14/FW-R15/FW-R17，P0/P1/P3局部推进。[规格](../specs/2026-10-26-macOS原生媒体流程.md)、[数字证据](2026-10-26-macOS原生媒体流程-evidence.json)。本轮使用Wails3.0.0正式构建和独立资料目录，真实模型账户按用户要求后置，模型请求及CLI推理均为0。

## 修复

候选添加成功后，界面会选择新片段并定位到它的开始帧。实际原生验收发现，工程修订使旧实时会话失效后，旧驱动仍负责阻止假播放，却也直接忽略了新的seek，导致60帧候选从第30帧开始，光标仍停在第89帧。`RealtimePlayback.seek`现对失效驱动保留明确的暂停位置，不发送旧控制、不启动RAF；新会话从这一位置准备。新增回归先观察到“expected 3 to be 1”失败，修复后通过，并检查旧消息、控制计数、播放阻止及卸载后位置。

保存重开时还观察到系统打开面板将刚保存的`.aividcut`文件置灰，完整路径及点击文件仍无法启用Open。工程打开选项现允许系统尚未识别的类型，保留推荐的`.aividcut;*.json`过滤及后端格式校验。仅工程打开开启此选项；媒体、LUT与重定位仍保持原过滤设置。`projectstore`的64MiB、普通文件、JSON结构和工程语义校验没有放宽。本轮没有修改上游Wails或关闭系统保护，也没有根据这一现象断言macOS类型缓存的内部根因。

## 实际原生流程

测试数据为自建640×360、30fps、48kHz视频：原镜头4秒运动测试图与440Hz单音，候选为4秒彩条与660Hz单音，另有未使用的自绘PNG任务。任务通过本地假适配器落盘，供应商标签不代表调用过模型。

1. 经系统Open选择原始工程，初始1素材、4轨、1片段、revision0。原片全精度实时预览实际准备成功，点击播放推进到3秒末端。声音推进由真实AudioWorklet链路完成；没有对主观听感作质量验收。
2. 从末端打开候选上轨，明确输入开始30、长度60、源入点0、新上层视频轨，选择“保留内嵌声音”。核对源音轨和混合提示后应用，得到2素材、5轨、2片段、revision1；新片段选中，光标正确为第30帧，实时准备成功，点击播放到第90帧结尾。
3. 一次Undo恢复1素材/4轨/1片段、revision2；一次Redo恢复2/5/2、revision3。旧原镜头保留，候选区间为半开`[30,90)`。
4. 保存到测试工程`native-input.aividcut`，经实际系统选择器重新打开。在最终构建中再次保存，并在同一进程再次Open该文件：文件可选、Open启用、重开仍为revision3和原2条片段。落盘候选未静音，工程不含会话token。没有新增“另存为”界面；本次是在已经指定路径的测试工程执行保存。
5. 实际导出窗口选择“工程原画幅”、H.264软件编码和整条时间线；合成自动选择明确显示本次使用原生合成。导出路径留空触发系统Save，另取`native-result.mp4`新文件名。任务从原生合成与编码进入已完成；随后独立检查真实成片。

## 成片核验

成片184100字节，H.264、640×360、30fps、90帧、3.000秒；AAC双声道48kHz，解码为144000个单声道样本。没有把界面任务成功当作唯一证据。

第15/29帧与原视频对应帧的RGB平均绝对误差为1.02784/0.97854；第30/45/89帧与候选源第0/15/59帧误差为0.21966/0.21925/0.21925，同位置错误下层画面的误差为123.86–125.12。误差来自有损编码及色彩转换，未声称像素逐字节一致。边界两侧证明上层候选从第30帧生效，原片段仍在下方。

0.2–0.8秒窗口的440Hz幅度0.12490、660Hz约0.00000635；1.2–1.8秒窗口分别为0.12435和0.12526，证明原声音持续存在且候选声音在后一区间参与混合。检测仅验证确定性音调，不代表自然语音、音色或响度质量。核验脚本、元信息与日志位于`work/native-workflow-check`。
