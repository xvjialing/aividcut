# 独立设置页面与原生菜单验收

日期：2026-10-30。对应 FW-R18、FW-R12/FW-R17。此记录接续同日的初版外观实现，按用户提供的两张设置截图和明确纠正，将“页头齿轮 + 弹窗”替换为完整设置页面；初版验收保留为历史。

## 本轮范围

- 移除工作台设置按钮；macOS 原有应用名菜单仅增加“设置…”一项，位置在 About 之后，保留原生服务、隐藏与退出等行为，提供 Cmd+,。其它平台在文件菜单中增加同一设置入口。
- 同窗口进入独立设置页面，左侧“返回应用”“偏好 / 外观”，右侧“主题”分组，明暗模式说明与浅色/深色/跟随系统三张缩略图。仅实现现有外观能力，不复制参考图中尚未实现的选项。
- 外观仍立即应用并保存同一 localStorage 偏好；保留跟随系统、错误提示与重试。缩略图用 DOM/CSS 绘制，原生 radio 提供键盘交互。
- 进入时暂停主时间线和源媒体；工作台 hidden/inert，保留组件实例、搜索/草稿/选区/滚动。返回恢复先前焦点，找不到时回到新建入口。设置中禁用隐藏工作台的快捷键，应用关闭保护继续工作。
- 设置有独立滚动区、文档标题与初始标题焦点；已有编辑对话框打开时先保留该对话框，不从原生菜单遮盖输入。

## macOS 原生实测

使用最终应用包的临时副本，独立 Bundle ID `com.aividcut.settingspagecheck`，通过 Info.plist 的 LSEnvironment 指定 `/private/tmp/aividcut-settings-native-data`，未操作用户实际工程。完成后从原生菜单正常退出该副本。

1. 原生工作台中没有设置按钮。
2. 点击系统菜单栏 AIVidCut，About之后有且仅有一个新增“设置…”，原有服务/隐藏/退出项保留。见[原生菜单可访问树](assets/settings-page/native-menu.txt)。
3. 点击“设置…”后窗口内容替换为完整设置页面，包含返回应用、外观导航、主题/明暗模式与三个radio，未出现dialog。见[原生设置页面可访问树](assets/settings-page/native-page.txt)。
4. 点击浅色模式，原生radio选中值和“当前显示为浅色模式”提示更新；返回工作台后按 Cmd+, 再次进入，浅色选择仍保留。
5. 从设置页点击原生 Quit AIVidCut，关闭保护完成空工程核对，进程正常退出。

本轮原生截图接口对隔离副本不可用，因此原生证据采用实际可访问树与交互结果；以下图片为真实浏览器联调截图，不冒充原生截图。

## 浏览器和布局验证

## 当前限制

Windows原生菜单布局未实机验证；原有账户、媒体性能和完整发行门槛保持。系统外观变化沿既有DOM事件回归覆盖，本轮未切换用户操作系统设置。首期设置只有外观，后续分类按实际功能增量接入。
