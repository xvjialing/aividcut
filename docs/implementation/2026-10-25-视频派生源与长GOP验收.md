# 视频派生源与长 GOP 验收

日期：2026-10-25。关联 FW-R01、FW-R11、FW-R12、FW-R15；P0/P1继续，完整产品目标未完成。Wails保持v3.0.0-beta.34，未重选客户端或前端框架。

## 变更与选择依据

原实现已经在远跳时定位到关键帧附近，不能预先断言长视频都会从头解码。本轮先记录90秒真实编码源，发现小画幅定位约3–4ms；主要可减少的工作是分割后反复打开解码器、重建首有效PTS锚和重复预卷。

Go图编译器现按素材身份/指纹、原入点/范围、速度、工程帧率和绝对放置相位复用视频producer，playlist的in/out引用原处理输出窗；外观、LUT和位置仍由每个片段自己的视觉transition处理。MLT允许同一producer被多次引用，in/out以其帧坐标为准。[官方XML说明](https://www.mltframework.org/docs/mltxml/)

MLT还会为重叠轨道克隆producer。worker现让相同配方/放置相位的克隆共享视频解码状态，不同放置相位独立。缓存最多8个，失活和Load释放；淘汰时解码器释放，而已借出的AVFrame保留独立引用。帧持有共享对象以保证回调寿命，RGBA后备转换使用保存的源时间基，避免淘汰后访问已关闭format。

原首有效PTS锚、实际CFR/VFR舍入、变速和矩阵方向保持不变；不通过平均帧率猜索引，不在每个派生入点重新开始fps。原采样音轨与零PCM画面定位接口继续保留。

## 自建夹具与正确性

新增 `cmd/preview-video-fixture`，只写新目录。源60fps，以8列×2行亮暗格编码16位源帧号，独立按阈值读取；VFR删除部分帧但保留原PTS。真实H264使用固定120帧GOP、CRF18、2个B帧并禁用自适应B帧和场景切换；ffprobe实查 `has_b_frames=2`。早期CRF0夹具实际没有B帧，已保留为中间记录，未用作B帧证明。

永久真实媒体回归覆盖：

- 长GOP的CFR/VFR、60→29.97、12345µs入点、0.5/1/1.5/2倍速，远跳、重复定位、回跳及32段切口前/后。实际源帧号与独立FFmpeg原输入→setpts→fps结果一致。
- 两个同源图层分别放在左右区域，相同放置相位实际仅打开1个解码器；错开5帧打开2个，分别显示正确源帧，构图不串用。
- 12个独立源身份同时合成，8状态缓存发生淘汰后借出的帧仍有效，合成帧号不变；Load之后缓存/活跃解码器归零。
- 原方向、LUT、文字、音轨、源相位和损坏输入回归继续通过。帧引用与异常路径经过ASan/UBSan，未新增消毒器日志；不把进程崩溃算作拒绝成功。
