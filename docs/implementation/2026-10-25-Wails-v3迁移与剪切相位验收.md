## Wails v3 与前端

用户恢复实施时明确要求 Wails 使用 v3 最新版。实际源码原为 v2.17.0，本轮已完成迁移。官方模块查询 `go list -m -json github.com/wailsapp/wails/v3@latest` 返回 **v3.0.0-beta.34**，发布时间 2026-10-20、最低 Go 1.26.0；模块、工程内 CLI 和 npm `@wailsio/runtime` 固定同版本。它仍是 Beta，最新版本与商业交付验收分别记录。[官方发布](https://github.com/wailsapp/wails/releases/tag/v3.0.0-beta.34)、[迁移指南](https://v3.wails.io/migration/v2-to-v3/)

`main.go` 使用 v3 Application/Window/Service，App 通过 ServiceStartup/Shutdown 管理生命周期；关闭按钮和应用退出共用草稿保护。`desktop.go` 统一文件选择器，附着编辑窗口，保留取消和过滤器。原 Bundle ID `com.wails.aividcut` 与资料目录规则保留。

前端 `lib/desktop.ts` 按需加载 Call.ByName/Events.On。普通开发浏览器不会初始化原生 IPC；桌面错误不向开发 HTTP 重复发送写入。官方绑定生成器核对为 1 个服务、85 个方法，名称为 `main.App.*`。前端继续采用 React 19.3.1 + TypeScript + Vite + Radix/共享组件 + CSS 变量；媒体队列与播放头单独处理，不由 React 逐帧搬运。

v3 Taskfile 替代旧 wails.json。`make setup` 安装与 go.mod 一致的 CLI；`make build` 检查版本并生成本地自签名 macOS 包。`work/bin/wails3 build GOOS=windows GOARCH=amd64` 实际生成 Windows amd64 exe。曾发现直接传 ARCH 会被 CLI 的宿主默认值覆盖，已更正使用 GOARCH，并按可执行文件构建元数据核对架构；项目 build.sh 对误用给出明确错误。macOS 13 只是构建声明，未测试旧系统；Windows 未进行原生运行和安装更新验收。

## 剪切处理相位

真实测试复现了 60fps→29.97fps 分割后画面取样改变、44.1kHz 非帧入点多切点出现新零采样，以及逐段重启 atempo 改变声音的问题。新增可选 `Clip.SourcePhase` 保留首次派生前完整输入与当前输出帧窗。旧 nil 工程以当前片段定义隐式配方，不猜成全素材选区。

分割、缩短修剪、复制、移动继承配方；滑动、更换素材、变速和超出原窗的延长重建输入。原声载体继承旧讲话配方，新画面重新处理。锁轨、深拷贝、整批撤销/重做、JSON 重开与人工字幕保护继续生效，前端只原样回传元数据。

视频按原首有效 PTS 处理 CFR/VFR/速度，再裁输出；音频先处理原完整重采样/atempo，再读派生输出窗。源单位量化差额不能分别搬到新时间线，避免粗剪闭合停顿时产生微小重叠。首尾保留原真实声音，原处理参考可在工程零点以前，不通过补静音或延长源 End 掩盖偏差。契约见 [剪切取样相位](../specs/2026-10-25-剪切取样相位.md)。

真实 PCM 回归覆盖 44.1/48kHz、12345µs 入点、0.5/1/1.5 倍速、多切点、Seek、直接 trim 与 split 删左。真实编码画面覆盖 CFR/VFR、60→29.97、240→60、0.5/1/1.5/2 倍速，以及核心命令实际递归分割；whole 与 joined 输出一致。

消毒器补查发现损坏源返回空帧时可在 MLT 包装层崩溃。现以有效占位帧安全退栈，主线程检查明确错误并拒绝输出，不将测试卡交付为成功。增强回归要求报错后仍能响应诊断，修复旧测试只检查异步 Done 而漏检崩溃的问题。原失败日志 `work/native-sanitized-evidence/ubsan.74051` 保留，修复后正常及 ASan/UBSan worker 均通过该回归。

## 视觉、预缓冲与资源

原生视觉路径支持用户旋转及部分强度 3D cube：源方向→fit/缩放→RGBA→用户旋转→tetrahedral LUT/原图强度混合→位置/透明叠加。真实图像和 YUV 视频已与 FFmpeg 像素对照；ROI 和缓存有界。完整色彩管理未完成，资源限制与误差见 [算子说明](../../native/mlt-worker/IMAGE_EFFECTS.md)。

AudioWorklet 在最多三包内预缓冲真实声音，目标 50ms；短流结尾或达到包上限可启动。真正欠载冻结内容时钟，补足后恢复，启动等待和运行欠载分别统计。Chrome 基线 worker 的正常播放/注入停顿恢复证据位于 `work/prebuffer-browser-check/`；本轮另验证更新后 worker 在 Wails v3 完整播放，不混淆版本。

`cmd/preview-benchmark` 可只读验证连续 RGBA/PCM，核对帧序/样本锚/文件与 worker SHA，记录每帧耗时和两个明确 PID 的 RSS/CPU。固定三份动态文件、三视频层、两声音及文字，共 39 片段、720p/30fps/240 帧的报告 `work/preview-load/phase-final-distinct.json`：p50 **12.478ms**、p95 **13.797ms**、最大 **38.511ms**，1/240 帧超过 33.33ms，384000 个双声道样本；worker 采样峰值 RSS **194002944** 字节，Go 诊断 **16416768** 字节。报告保留其版本指纹；随后另有损坏源处理修复，不能将旧指纹称为新二进制。

这里只计原生 Next，不含 WebView、传输、设备声音和整个进程树。共享页、采样漏峰、短素材与 atempo 前缀重放均有边界，不能据此承诺长素材或 Windows 实时。
