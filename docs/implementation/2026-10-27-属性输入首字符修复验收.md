## 缺陷证据

最新费用参考构建的隔离副本中，长度原为 360。原生工具确认选中了 `360`，单步按键 `1` 后，实际输入事件已到达控件，DOM 值为 `1`；随后界面恢复 `360`。连续输入可能变成 `36020`，并被素材余量校验拒绝。无效值关闭时“保存并关闭”禁用，明确放弃后才退出，原工程修订保持 13。

私有诊断使用同一版应用和独立资料目录，记录限定测试控件的 DOM/React 事件。本轮修复前两个数字 input 均真实到达，但没有对应的 React 数字变化回调；草稿文件曾保存 `3602`，而可见控件仍显示 `360`。这证明不能再把全部现象归为自动化焦点不可靠。

共享 `useInspectorDrafts` 在 `onInputCapture` 内同步更新“等待保护”提示，引起父层刷新。在子控件的受控 onChange 生效前，旧值被写回。新增捕获/冒泡之间刷新离散更新的回归，修复前数字得到 `360` 而非 `1`，文字得到“原标题”而非“首”，两项均失败；与实际原生症状一致。

## 修复

原始输入继续同步收集，等待提示通过下一任务刷新，保留既有一秒合并写盘。提示定时器在中文组合开始和组件卸载时取消，回调复核挂载、组合和写入版本。旧写入回执完成而更新输入尚未落盘时，保持“等待保护”，不误称最新输入已经保护。

没有更改数字边界、失焦提交、统一编辑命令、工程格式、凭据或草稿恢复权限。正常数值和文字输入通过同一个共享 Hook 修复，未加平台特例或按键替换补丁。
