# 应用默认图标修复验收

日期：2026-10-30。关联 FW-R12、FW-R14、FW-R17。范围为 Mac 启动时显示的应用图标与构建资源；不新增菜单栏托盘功能。

## 用户纠正与最终实现

用户随后明确指出“左上角不是有一个现成的图标吗”，要求复用界面现有图标。首次采用 favicon 的 A 标识理解有误，当前以左上角场记板为唯一图案依据，浅蓝背景、深色线条、尺寸与圆角全部沿用 `.brand-mark`；界面左上角不变。

新增 `scripts/export_app_icon.mjs`，直接用已安装的 React/Lucide `Clapperboard` 渲染同一图案，读取 `App.tsx` 的 19px 图标尺寸、`app.css` 的 28px 容器/7px 圆角及 `tokens.css` 的两种实际颜色，输出 `build/appicon.svg` 与 `frontend/public/favicon.svg`。不手绘另一份路径，也不保留 A 字母为活动图标。`build/appicon.png` 从该 SVG 导出为 1024×1024；已有 Wails 嵌入与 `.icns` 生成链路沿用。

维护时先运行 `node scripts/export_app_icon.mjs`，再使用 SVG 渲染工具将 `build/appicon.svg` 导出为 `build/appicon.png`。此次仍使用已存在的本机 Qt SVG 导出工具，不把 Qt 开发 SDK 加为普通应用构建的新依赖。SVG 展平视口以兼容其 SVG Tiny 渲染器。

## 首次修复记录（图案选择已被用户纠正）

用户反馈启动后仍显示 Wails 默认 W 图标。检查发现 `build/appicon.png` 仍为框架默认图片，Mac 打包脚本还会复制上次 `.app` 中的 `iconfile.icns`，首次构建也没有从源图标生成资源。Wails 初始化未提供运行图标。

复用已有 `frontend/public/favicon.svg` 的深色底、浅蓝 A 标识，将其导出为 1024×1024 的 `build/appicon.png`。此次导出使用本机现有 Qt SVG 渲染器，没有下载新组件，不增加应用或日常构建依赖；原矢量标识及窗口内场记板保持。

`main.go` 嵌入该 PNG 并传入 `application.Options.Icon`；Mac 构建使用工程固定版本的 Wails CLI 从该 PNG 生成新 `.icns`，路径与 `Info.plist` 的 `CFBundleIconFile=iconfile` 一致。旧 `.app` 不再是图标来源，首次与增量构建共用同一逻辑。
