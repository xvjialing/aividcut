# 音轨资源与纯画面定位验收

日期：2026-10-25。关联 FW-R01、FW-R05、FW-R11、FW-R12、FW-R15、FW-R17；继续 P0/P1，保留全部 P0–P6 目标。客户端仍固定 Wails v3.0.0-beta.34，Go/CLI/npm runtime 同版本。

## 实现范围

- 受控音轨改用 `aividcut.audio_mix`，仅对48kHz双声道、交错float32的共同全局样本窗求和，跳过时间线空白。格式/长度不符明确报错，不取较短长度或增加静音掩盖差异；音量仍在片段层应用。
- 同素材身份/指纹、完整源范围、速度和处理时间原点的派生片段共享原处理器。缓存最多8个，按使用时刻淘汰；失活后释放，重新Load清空。每个处理器的PCM队列最多192000采样帧，当前保留约1秒附近输出；不会预渲染整段素材。
- `Session.Preview` 仅定位画面，返回 `pictureOnly=true`、`samples=0`；完整Seek继续返回真实PCM，Next从目标帧准备实际声音。应用准备/暂停/定位使用画面入口，播放仍由真实PCM消费推进。旧后端没有该入口时保留真实完整Seek。
- 后端拒绝将纯画面帧送入播放队列；前端快照立即绘制并确认，不送Worklet。播放准备、预缓冲、欠载冻结和epoch隔离继续沿用原逻辑。
- 新增 `cmd/preview-fixture`：在新目录写出真实音轨和整段/实际核心分割工程。诊断命令增加实际PCM CRC及有序定位列表、逐点耗时和音频处理计数，仍不修改工程或调用模型。

通用MLT mix含两份192000×6通道float缓冲，合计9216000字节保留容量；实际驻留取决于触页，不能直接乘片段数冒充RSS。本轮用真实测量区分容量与驻留。[MLT 7.42 源码](https://github.com/mltframework/mlt/blob/v7.42.0/src/modules/core/transition_mix.c)

## 定位与声音准备

在同一5分钟源上按 `0,5800,5800,2,4500,4500,0` 定位：完整音频Seek的p50/p95为22.421/223.966ms，纯画面定位为2.670/3.309ms。定位前后诊断证明纯画面阶段没有打开源处理器、构建音轨滤镜或重放音轨。完整音频定位保留，之后的Next仍取得准确的目标PCM；冷音频准备耗时只是移到播放预缓冲，不能声称它已消失。

报告 `work/audio-load-long-300/{final-seeks,final-picture-seeks}.json` 保留请求顺序、重复点、逐点图像/音频CRC、实际样本锚与计数。帧5800约在输出193.53秒处。7个点只是这条固定音轨的调用序列，不代表通用定位分布；原生视频画面本身的定位成本另测。

## 压缩配音与时钟修复

新增MP3、M4A/AAC、FLAC真实编码回归，实际计数后执行多次剪切，并与独立FFmpeg源采样时钟参考逐样本比较：

- AAC在开头含负PTS priming包。探测/解码在文件开头保留原始包，避免seek到零点后跳过首个有效块；靠后读取预留一秒，回跳重开以恢复正确解码状态。
- MP3部分skip/discard需要解码器的 `pkt_timebase`。原实现未设置时无法更新有效样本PTS，导致错误起点和重采样相位；探测与流式解码现均设置实际包时间基。
- 参考路径以首个有效解码样本归零，先 `asetpts=N/SR/TB` 再重采样，与工程的源采样契约及导出路径一致。对照浮点误差上限1e-6，不通过移动参考、丢样本或增加静音通过测试。

0.125/8倍速边界另有真实音高和Seek回归。相同相位但不同音量的副本、独立放置/静音、12路并行缓存驱逐、随机回跳、重新Load及损坏源错误后存活都有回归。

## 剩余边界

以上只计原生媒体吞吐及两个明确PID的定时RSS采样，不含整个WebView/客户端进程树或硬件声音；采样可能漏峰，共享页不能简单相加。原生图仍限制128片段；超过8个不同音轨处理配方同时请求会发生淘汰与重放，真实大工程容量未完成。音轨缓存不替代视频解码/定位、GPU、完整字体色彩、Windows实机和正式媒体SDK分发许可。完整模型账户、声音质量、Seedance和两种CLI目标继续按原路线图推进。
