# 前端 pnpm 迁移验收

日期：2026-10-30。关联 FW-R11、FW-R14、FW-R15、FW-R17 的开发与交付链路。用户要求切换当前前端依赖管理方式，以便复用磁盘上的依赖内容。

## 实施范围

- 使用本机已有 pnpm 12.15.0，在 `frontend/package.json` 固定 `packageManager`；原 npm 锁导入为 `frontend/pnpm-lock.yaml`，不再保留活动 `package-lock.json`。
- 比较全部锁定包身份，原有 164 个包版本均保留，仅新增构建依赖 `yaml@2.9.1`，用于正确解析 pnpm YAML 锁文件，不进入客户端运行环境。
- `frontend/pnpm-workspace.yaml` 采用隔离布局和 `pmOnFail: error`；复用同磁盘的用户内容 store，不启用实验性全局虚拟 store，不修改全局 pnpm 配置。
- `make setup/dev/build/run/test/check` 的前端安装和执行改用 pnpm，安装固定为 `--frozen-lockfile`；前端 README、根 README 和 `premium-ui.json` 同步。
- Vite 清单升级为 schemaVersion=2，绑定 pnpm 锁文件名、SHA256 和包管理器身份。Vite 与 Python 收集器共用锁解析器，正确区分包管理器与应用多文档；实际包从 `.pnpm/.../node_modules/...` 读取，锁定版本/integrity 与内部路径边界继续验证。
- 更新生产嵌入检查和第三方声明夹具，增加 pnpm 虚拟目录、外部链接拒绝、锁摘要/integrity 不一致与多 YAML 文档回归。组件生态名称仍为 npm，表示 npm registry 包身份，不代表继续使用 npm 安装。

- 原 164 个锁定包身份全部保留，唯一新增为 `yaml@2.9.1`。活动 npm 锁文件已移除；验证后旧 npm 安装目录已删除，不保留两套安装。

## 使用方式

根目录日常命令保持 `make setup`、`make dev`、`make build`、`make run`。仅处理前端时：

```sh
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend run dev
pnpm --dir frontend test
pnpm --dir frontend run typecheck
```

本机正常权限安装实际使用 `/Users/xvjialing/Library/pnpm/store/v11`，pnpm 报告通过 clone 从内容 store 进入项目虚拟目录。沙箱若不允许访问/链接用户目录，会选择项目内 store；为跨项目复用，应在可访问用户 store 的终端安装。共享 store 可用于其它使用相同包内容的项目，未清理全局 npm 缓存或其它工程依赖。

`du` 和文件大小不能给出 APFS 共享 clone 的整盘物理节省量；本次只记录当前工程目录前后值、旧安装清理和实际 store 使用，不承诺同等数值的整盘空间净增加。
