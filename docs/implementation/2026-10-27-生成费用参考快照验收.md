# 生成费用参考快照验收

2026-10-27，FW-R09/FW-R10/FW-R11/FW-R12，P3/P5。对应[规格](../specs/2026-10-27-生成费用参考快照.md)，补齐规划内生成成本估算的手动参考方式；账户、供应商实时报价和实际账单继续待验。

## 实现范围

生成核对窗口新增选填费用参考，复用现有 Field/Input/Select、Modal 与任务卡，不改变工作区配色或组件库。支持 CNY/USD，以及每次请求、每张图片、每秒视频三种单位。图片按请求数量计算，视频秒价要求显式正整数时长；整次请求报价数量为一。九位整数、六位小数和一百万计价单位上限另有溢出检查；Go/TypeScript 使用整数和十进制字符串，不用浮点金额。

首次核对默认未填写，明确未知与零。返回修改后重新核对不沿用旧单价，配方和候选复用也不携带价格。提交回执未知时，原请求 ID 和原估价（含未填写）一并保留并锁定核对，不能改价后创建第二个原请求。单价无效时显示关联错误并聚焦字段，Enter 输入和关闭核对框不会直接提交。复核时另修复前端失败重试缓存缺少工程标识的问题：不同工程不继承原请求编号或参考价，后端原有跨工程拒绝保持。

Go 任务协调器重新计算估价，并与连接、工程和生成请求一同签名去重。有估价保存为 v2；无估价保持 v1 字节级签名契约。加载时重新计算单位、数量和金额，损坏记录占住原 ID。任务等待、失败、取消、未知、成功及恢复均保留提交时估价，不推断扣款或退款。

估价只进入本地任务，未进入供应商 Request、Recipe 或工程资产。原 MCP 生成请求未提供人为估价时继续显示未知，共用同一任务核心；未扩展模型的支付权限。没有添加默认供应商价格、汇率、实际账单或预算控制。

## 验证结果

- 29 项共享 JSON 样本由 Go 和 TypeScript 分别读取，覆盖 `0.1 × 3 = 0.30`、六位小数、CNY/USD、请求/图片/视频单位、接近 int64 上界、显式零、默认时长拒绝、负数/指数/全角/超精度/溢出等。
- 任务协调器实际写盘/重开、相同规范价去重、同 ID 改价拒绝、读出副本隔离通过。金额/数量/来源/版本篡改即使重算签名，加载仍拒绝并保留原 ID。既有 unknown 和停止等待→重启→查询原任务回归补充估价保持验证，生成 POST 不增加。
- 前端 61 文件、424 项测试通过，新增五项 DOM 流程覆盖核对前不提交、金额与供应商参数分开、错误聚焦/变参清空、网络未知后锁定原请求/估价及视频零参考价。Typecheck、格式、生产构建、生产嵌入资源检查和相关 vet 通过。
- 显式随包媒体 SDK/FFmpeg 环境中，generation、generationjobs、application 三包竞态通过；应用包实际耗时约 35.3 秒。特定自然素材和账户用例仍按各自环境门槛执行，不将跳过的用例算成实际通过。
- premium 严格静态审计零发现。DESIGN.md 沿用现有 token，UX-CONTRACT.md 更新费用核对变体；本次未改变布局 token。

## 实际浏览器与本机服务

私有开发夹具使用真实应用桥、连接租约、OpenAI 适配器、协调器和结果导入器，将网络请求限定到本机固定 PNG 服务；凭据保存在测试内存，不读取系统账户，不调用真实模型。夹具仅位于 `work/`，未进入客户端包。

实际完成三张图片请求，手动填写每张 CNY 0.1，核对框显示 CNY 0.30；确认后得到三个本地候选，任务卡显示同一费用。固定服务实际只收到一次 POST，且请求体无估价字段，落盘 v2 的 Request/Recipe 也无估价。刷新和完整停止/重启测试后端后仍读取 CNY 0.30，POST 总数保持一次。

实际输入 `1e-2` 被拒绝并聚焦单价，修正为 0.1 后可继续。原生计价单位菜单的打开/退出、Tab 焦点顺序已检查。900×720 窄窗中核对框宽 460、可视高度 686、内容高度 777，无横向溢出，内部可滚动；六位单价显示 CNY 0.000003，Enter 不提交，Escape 取消后请求数不增加。测试后恢复默认视区，关闭临时页面和本轮服务。
