# 背景与需求规格

基线日期：2026-10-24。本文将用户明确要求与会话中的设计建议分别记录。用户原始表达见 [需求对话原文](../archive/2026-10-24-需求对话原文.md)。

## 背景和目标用户

用户希望开发一款 AI 视频剪辑软件，服务于已有一定剪辑基础、希望节省时间的人。软件需要保留普通剪辑软件的预览和多轨操作，同时借助 AI 分析素材、简化编辑并生成所需素材。

设计需要同时考虑产品经理与摄影剪辑人员视角：功能覆盖清楚、模块可以扩展，日常操作符合剪辑习惯，参考素材、候选镜头及时间线应用方便。AI 的结果需能继续人工调整。

## 从需求推导的当前设计建议

- 以可编辑工程和统一命令为基础，人工、AI、工作流共享撤销和版本。
- 优先评估本地工程与本地渲染；云端分析和生成单独适配。完全离线不是用户已确定要求。
- 首个重点验证场景建议是口播、教程或讲解；用户尚未将产品永久限定于该场景。
- 通过字幕源时间映射、模型能力目录、持久任务和生成素材落盘提高可靠性。
- 先跑通各一个图片/视频模型和一个 Agent，再扩展剩余接入；最终覆盖不能因首个演示成功而标为全部完成。
- 用户已确认 Wails + Go 客户端路线，后续明确使用 v3 最新版，当前Go/CLI/runtime固定v3.0.0正式版，项目工具链Go1.27.3；前端推荐 React + TypeScript + Vite，按需组合组件和状态工具。SQLite 和 MLT/FFmpeg 仍为对应模块候选，见 [前端评估](../research/前端展示层框架评估.md) 与 [决策记录](../implementation/决策与待确认事项.md)。

## 首个完整使用流程

导入讲解素材 → 手动分割与音画链接 → 转写和素材分析 → 口播粗剪 → 编辑字幕 → 生成指定音色配音 → 生成配图 → 图片生成补充镜头 → 比较并添加/替换 → 应用 LUT → 手动精修 → 导出 → 关闭重开 → 验证恢复与撤销。
