# AIVidCut

面向具有一定剪辑基础、希望节省时间的用户，将多轨视频编辑、素材理解、字幕配音、图片与视频生成及本地 Agent 自动化结合起来的桌面软件项目。

`AIVidCut` 为用户已确认暂用的英文工程名：AI 表示智能能力，Vid 取自 Video（视频），Cut 表示剪辑与镜头编排。目录名为 `aividcut`，产品定位为 AI-powered Video Editor。

素材卡现已按可见区读取真实缩略图，选中视频可通过五张取样或键盘滑条浏览源画面；真实缺失重试、同一工程重开撤销旧能力、210项前端测试与双端构建通过，见[素材浏览验收](docs/implementation/2026-10-25-素材缩略图与源画面浏览验收.md)。源取样不包含时间线效果，新界面双端原生、代理与完整阶段仍待验收。

视频派生源已增加同配方复用及8状态缓存；720p/90秒/64段固定夹具的切片尖峰从49ms降到8ms，独立帧号、重叠图层和淘汰引用回归通过，见[视频长GOP验收](docs/implementation/2026-10-25-视频派生源与长GOP验收.md)。这不代表整个视频容量或Windows实机已完成。

需要 Go 1.26+、Node.js（见 `frontend/package.json` 的 engines）与 pnpm 12.15.0、Python3.9+ 和目标平台的原生构建工具。已有 Corepack 时可用 `corepack enable pnpm` 准备 pnpm 命令。Python与前端依赖只用于开发/构建，最终客户端与Windows诊断工具运行不需要它们；材料/绑定用法见[依赖声明说明](scripts/DEPENDENCY_NOTICES.md)。初次准备：

```sh
make setup
```

`make setup` 从 go.mod 安装同版本的工程内 `work/bin/wails3`，构建使用 v3 Taskfile；Go/CLI/runtime均固定为正式版3.0.0。go.mod保留1.26语言基线，项目工具链为go1.27.3，首次可由Go自动下载；CLI也使用项目实际工具链编译。运行 `go list -m -json github.com/wailsapp/wails/v3@latest` 可重新核对上游，升级需同步依赖并重新验收。

macOS 日常完整构建与启动：

```sh
make build  # 完整构建，包含媒体运行库
make run    # 完整构建后启动原生客户端
make open   # 直接打开已有构建，不重新编译
```

应用输出为 `build/bin/AIVidCut.app`。更新后要运行新版本，请先正常退出已运行的客户端；`make open` 使用系统打开应用，已有实例可能只会回到前台。`make run` 不提供热更新；浏览器开发仍用 `make dev`。

`make build` 默认读取 `work/media-runtime/darwin-arm64/`（Apple Silicon Mac）；其它目标使用 `work/media-runtime/<GOOS>-<GOARCH>/`。目录内需要已经装配并核验的 `runtime.json`、FFmpeg、FFprobe、MLT/Qt、worker 及数据文件。本机现有 SDK 已复制到固定目录，日常无需再填地址；新电脑/新检出需先取得对应 SDK，`make setup` 不会下载第三方媒体运行库。缺失、损坏或平台不匹配会停止完整构建，详见[装配说明](docs/implementation/媒体SDK装配说明.md)。

`AIVIDCUT_BUNDLE_MEDIA_RUNTIME` 是**构建时媒体运行库的来源目录**，打包脚本会将其复制进应用；用户运行 `.app` 不需要这个变量。仅切换 SDK 时按需覆盖，例如 `AIVIDCUT_BUNDLE_MEDIA_RUNTIME=/absolute/path/media make build`。底层 `make build-app` / `./scripts/build.sh` 仍允许只构建应用，未提供变量时不带媒体库，不能当作完整交付。

完整包启动时可自动发现随包媒体工具。客户端也可在“任务 → 媒体工具设置”选择绝对路径，检测后保存并重启生效；设置不进入工程包。开发终端仍可使用环境变量，当前不会自动读取 `.env`：

```sh
export AIVIDCUT_FFMPEG=/absolute/path/to/ffmpeg
export AIVIDCUT_FFPROBE=/absolute/path/to/ffprobe
make dev
```

Windows 完整交叉构建使用 `GOOS=windows GOARCH=amd64 make build`，需要预先准备 `work/media-runtime/windows-amd64/` 或显式指定 Windows SDK。只检查应用编译可用 `GOOS=windows GOARCH=amd64 make build-app`；交叉编译不代表安装器或 Windows 实机完成。

`make dev` 启动真实 Go 开发服务（127.0.0.1:43110）和 Vite（127.0.0.1:5173）。浏览器模式使用路径框进行本地导入/保存；桌面版使用系统文件选择器。正式构建的前端只接受 Wails 桥，不会静默回退到假工程或开发 HTTP 接口。

实验实时合成需要另行准备明确的 MLT/FFmpeg/Qt 开发 SDK，再运行 `make native-worker`。SDK 变量、构建与验证命令见 [worker 说明](native/mlt-worker/README.md)。完整构建成功后，`make dev` 使用工程内生成的 worker/repository/profiles，显式环境变量优先；未配置时实验预览说明不可用原因。该入口只构建本项目 worker 与开发 symlink，不安装系统依赖或打包第三方媒体库。

```sh
make test
make check
make build
```

发行候选可用 `make release-audit` 生成只读清单，`make release-check` 核对真实嵌入资源及当前缺项。用 `AUDIT_CONFIG=/absolute/path/config.json` 指定输入；完整打包不等于正式发行验收通过，许可与签名等门槛保持。命令约束与退出码见[发行检查说明](internal/releaseaudit/README.md)。

完整 `.app` 可以整体复制到兼容的 Mac，运行无需另装 Go、Node、Python、Homebrew、FFmpeg 或 Qt。当前本机 SDK 为 Apple Silicon arm64，其中部分媒体二进制声明最低 macOS 26；主程序的 macOS 13 声明不能代表整个包支持旧系统，Intel 与旧版 macOS 需另行装配兼容 SDK 并实机验收。签名目前为本地自签名，商业签名、公证和安装更新仍需后续工作。Codex/Claude 功能仍需另装并登录相应 CLI，模型连接与用户工程/素材独立配置和迁移。

桌面持久资料默认位于系统用户配置目录下的 `AIVidCut`，预览位于用户缓存目录。`AIVIDCUT_DATA_DIR` 可以指定独立开发目录。连接资料与生成结果不会放在仅供清理的预览缓存中；同一个持久目录同时只允许一个写入实例。

## 目标功能（完整范围）

- 本地素材、预览、视频轨、音频轨、文字轨和字幕轨，以及常规非线性剪辑。
- 素材内容分析、口播粗剪、转写与可编辑字幕。
- 指定音色及自定义音色的配音。
- `.cube` LUT 导入、复用、强度控制，以及预览导出的一致性。
- 图片生成与修改、视频生成、候选镜头管理和时间线添加/替换。
- 调用本机 Codex CLI、Claude Code，通过 MCP 和可复用工作流执行编辑。
- 所有入口共用工程状态、剪辑命令和撤销历史；按创作任务组织模型选择。
